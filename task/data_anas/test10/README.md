# Test10：10 轮客观连续任务集

这组任务用于替换主观性较强的 12 轮调研/设计任务。场景采用固定的零售补货调度数据，所有关键结果都有标准答案，可用于比较多 agent 系统在**连续记忆复用、数值计算、约束检查、异常重规划、最终审计汇总**上的表现。

## 文件说明

| 文件 | 用途 |
|---|---|
| `tasks.json` | 10 轮任务定义，包含依赖、输入引用、输出格式和客观校验点 |
| `tasks.py` | 与现有 `TASKS` 列表风格兼容的 Python 任务定义 |
| `data.json` | 固定源数据与全部确定性规则 |
| `answer_key.json` | 每轮标准答案，供人工或脚本评分 |
| `scoring.md` | 建议评分方法和扣分规则 |

## 设计目标

- **客观**：每轮输出都有可核验的数值、JSON 字段或布尔结论。
- **连续**：R02-R10 依赖前面轮次的结果，适合测试共享记忆和跨轮检索。
- **多 agent 友好**：自然拆分为数据读取、计算、约束校验、计划生成、复核总结等角色。
- **无外部知识**：只允许使用 `data.json` 和前序轮次输出，不需要联网或框架背景知识。

## 使用建议

1. 每轮将 `tasks.json` 中对应任务的 `query` 发给系统。
2. 运行器应把 `data.json` 作为固定上下文，或至少在 R01 注入完整数据。
3. 每轮输出尽量要求 JSON，方便与 `answer_key.json` 自动比对。
4. 最终 R10 用 checksum 做端到端一致性检查。

## 客观主线

| 轮次 | 目标 | 主要客观指标 |
|---|---|---|
| R01 | 汇总需求、库存、缺口 | SKU 总需求、总库存、缺口 |
| R02 | 按优先级分配库存 | 店铺-SKU 满足/缺货矩阵 |
| R03 | 按最近仓分配货源 | 仓库到店铺的 SKU 货源矩阵 |
| R04 | 汇总重量、体积、毛利 | 每条仓店线路载重/体积/毛利 |
| R05 | 装车与容量校验 | 车辆载重、体积、容量是否通过 |
| R06 | 路线里程和到达时刻 | 每车里程、每店到达时间、准点性 |
| R07 | 道路中断影响评估 | 延误分钟、罚金、无缓解总成本 |
| R08 | 缓解方案选择 | 三个方案成本对比与最优方案 |
| R09 | 财务 KPI | 履约率、毛利、物流成本、净贡献 |
| R10 | 最终审计汇总 | 所有关键字段和 checksum |
