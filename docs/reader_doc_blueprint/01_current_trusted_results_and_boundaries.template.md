# 模板 01：当前可信结论总览

建议目标文件：

- `docs/reader_guide/01_current_trusted_results_and_boundaries.md`

## 一、文档目标

这份文档是所有读者的最短入口。它先回答：

1. 现在到底已经正式成立了什么。
2. 现在还没有正式成立什么。
3. 哪些是 headline，哪些是 support，哪些是 audit。

## 二、必须使用的输入

1. 当前冻结 docs
2. 当前 communication authoritative artifact
3. communication support artifact
4. typed-state support artifact
5. memory artifact

## 三、建议章节结构

### 1. 先给读者的结论

要求：

1. 用 5 到 10 句话总结当前最可信结论。
2. 先写当前正式成立的内容，再写边界。
3. 不允许一上来就堆 artifact 路径。

### 2. 当前正式结论分层

必须有一张表，至少包括：

- 对象名
- 当前角色
- 当前能正式说什么
- 当前不能说什么
- 主证据路径

### 3. authoritative artifact 清单

要求：

1. 列出 communication、typed-state、memory 当前主要证据路径。
2. 每条路径要写“它回答什么，不回答什么”。

### 4. 当前已经成立的结果

至少覆盖：

1. communication 当前读法
2. typed-state 当前读法
3. memory 当前读法

### 5. 当前不能误读成什么

至少覆盖：

1. 不能误读成 overall superiority
2. 不能误读成 memory superiority
3. 不能把 support 写成 headline
4. 不能把 communication gate 和 formal stability gate 混为一谈

### 6. 当前边界与下一步边界

要求：

1. 写清楚当前为什么还要保留 boundary。
2. 写清楚“下一步允许做什么，不允许做什么”。

## 四、必须解释的术语

第一次出现时至少解释：

- `headline`
- `support`
- `audit`
- `authoritative artifact`
- `communication gate`
- `formal stability gate`

## 五、验收清单

1. 新人读完能知道“现在到底成立了什么”。
2. 读完不会误以为所有正向结果都已经 closure。
3. 文档里有明确的 artifact 路径锚点。
4. 没有把 typed-state 或 memory 偷换成主 headline。
