# 模板 03：系统架构与数据流说明

建议目标文件：

- `docs/reader_guide/03_system_architecture_and_dataflow_explainer.md`

## 一、文档目标

这份文档是新人真正理解项目结构的核心文档。它必须回答：

1. 当前最新架构是什么。
2. 每个模块做什么。
3. 数据如何从任务流到结果。
4. 四角色、三平面、五层架构分别是什么关系。

## 二、必须使用的输入

1. `agents/`
2. `runtime/`
3. `protocol/`
4. `statepool/`
5. `memory/`
6. 当前架构说明文档

## 三、强制组织方式

必须按三套视角交叉解释，不能只按目录树讲。

### 视角 A：五层架构

建议至少写成：

1. 任务合同层
2. 编排语义层
3. typed state 基座层
4. replay / 记忆门控层
5. 报告与结论边界层

### 视角 B：三平面

至少解释：

1. 控制面
2. 状态面
3. 记忆面

### 视角 C：四角色

必须写死：

1. `Planner`
2. `Retriever`
3. `Executor`
4. `Summarizer`

并显式写明：

- `validate` 不是第五个 Agent

## 四、建议章节结构

### 1. 总架构图

要求：

1. 至少一张 Mermaid 总图。
2. 图里要同时体现角色、平面和关键对象。

### 2. 为什么需要三套视角

要求：

1. 解释为什么“层”“平面”“角色”不能混写。
2. 说明这三套视角分别帮助读者理解什么。

### 3. 五层架构逐层解释

每层都要说明：

1. 作用
2. 主要输入
3. 主要输出
4. 和上下游的关系

### 4. 三平面逐面解释

每个平面都要说明：

1. 承载什么信息
2. 为什么不该放到别的平面
3. 当前代码里落在哪

### 5. 四角色逐角色解释

每个角色都必须有：

1. 输入
2. 输出
3. 依赖哪些对象
4. 在 `text` 和 `StateBus` 路径下有什么差异

### 6. 核心对象字典

至少覆盖：

- `SampleTask`
- `Plan`
- `PlanStep`
- `StepResult`
- `StateRef`
- `MemoryHit`
- `MemoryCommit`
- `RunContext`

要求：

1. 每个对象都要说明“它是谁、从哪来、传给谁、谁消费它”。
2. 不允许只给类名。

### 7. 单任务时序图

要求：

1. 用一个真实任务画完整时序。
2. 时序里要体现任务进入、计划、检索、执行、总结、记忆写回。

### 8. 当前最容易误解的点

至少解释：

1. `validate` 和 Agent 角色的关系
2. `memory` 和结构化通信不是两条平行主线
3. `StateRef` 不是简单字符串 ID

## 五、验收清单

1. 新人能区分四角色、三平面、五层架构。
2. 读者能说清一个对象是怎么流动的。
3. 至少有一张总图和一张时序图。
4. 文档不只是“目录说明书”。
