# StateBus v2 答辩终版 10：演讲材料总入口

这组材料服务于 [StateBus-v2-答辩终版-10.pptx](../StateBus-v2-答辩终版-10.pptx)。它不是把页面文字重新抄一遍，而是把 PPT、[项目说明书](../项目说明书-总.pdf)和 [v2 实现手册](../../implementation/README.md)组织成一条可讲、可追问、可回到代码和实验来源的答辩叙事。

整套 PPT 共 28 页，推荐按 14—16 分钟准备，其中作品演示约 90 秒。章节页 P3、P7、P15、P19、P26 只承担转场，不展开内容；真正需要形成完整论证的是 P4—P6、P8—P14、P16—P18 和 P20—P25。若现场时间缩短到 10 分钟，可使用[时间控制与删减方案](08-时间控制与删减方案.md)，不要临场随机跳页。

## 信息来源优先级

本材料采用以下优先级处理来源冲突：

1. 当前 `v2/` 代码、`tests/v2/` 与 [implementation](../../implementation/README.md) 说明实现事实。
2. 当前 PPT 可见页面和固定实验文档说明答辩展示口径。
3. 项目说明书提供背景、完整架构和正式书面表述。
4. PPT 内嵌备注只作历史参考，和当前实现冲突时不采用。

这一优先级很重要。当前 PPT 文件内部仍残留早期备注，出现过“5 个 Agent”“Latent KV”“KV handle”等旧方案表述；可见页面和正式 v2 实现已经改为 Planner、Retriever、Executor、Summarizer 四角色，以及 `SemanticStateRef` 驱动的稠密语义状态。答辩时不要照读旧备注，也不要把 KV cache、hidden state 或跨模型 tensor 传递说成已完成能力。

## 全场必须稳定的六句话

整场无论怎样压缩，都应保持以下事实不变：

- StateBus 解决的是多 Agent 协作基础设施问题，不是再造一个聊天工作流。
- Agent 负责语义推理，Runtime 负责计划批准、能力授权、对象引用、消费回执、质量验证和失败收敛。
- 控制面是 `UDS + typed Protobuf`，但亮点不只是“用了 Protobuf”，而是协议字段进入了 Runtime 权限与生命周期。
- 非文本主证据是 `float32` 语义矩阵通过 `SemanticStateRef` 被不同 PID 的消费者真实读取，并改变后续证据选择；LLM 不直接读取 embedding。
- 记忆的主指标是 actual-use，不是候选命中；兼容门拒绝不合格历史后，当前任务继续重算。
- CodeAct 的可信输出不是模型源码，也不是退出码，而是通过 Policy、隔离执行和业务 Validator 后的 verified `ExecutionArtifactRef`。

## 实验数字的固定口径

PPT 主实验沿用固定代码/实验基线 `bda1774`：95/95 正式执行通过；10 个同任务完整链对照中，总 Token 降低 47.40%，wire bytes 降低 64.85%，总耗时降低 6.32%，质量保持 10/10；结构化控制字节降低 83.05%；非文本状态 9/9 跨 PID 消费并改变选择；连续任务记忆 actual-use 为 7/20，即 35%，39/48 个不兼容候选被拒绝；能力覆盖 25/25，通过路径为 18 个受限 Python 和 7 个 DSL，fallback 为 0。

P25 显示的 `558 passed` 属于这套 PPT 的固定基线。7 月 27 日新增 Logit Retry Gate 后，当前全量回归为 `582 passed`；该机制另有 12 个受控挑战 case，但没有改写 95/95 正式业务基线。默认主讲稿不把这两套分母混在一起，只有被问到新增机制时才按[问答文档](06-评委问答与口径边界.md)补充。
