# 作品演示操作与讲解脚本

P27 的目标不是证明“网页能动”，而是让评委在 90 秒内看到一个真实任务怎样形成 TaskSpec、EvidencePack、StateRef、执行程序、verified Artifact 和 ClaimSet。界面动画只是事实的呈现方式，讲解始终围绕对象和回执。

## 推荐演示策略

最稳妥的主方案是播放一段由真实 Run 录制的 90 秒视频，同时现场讲解。页面标题本身就是“作品演示播放”，而快速任务标注的实际运行时间约 1—3 分钟，临场等待会破坏节奏。录屏不是模拟：它应来自 Studio 保存的真实 Run，并完整展示 task-flow、生成程序、Validator 和结果。

现场还应提前打开可交互的 Studio。评委要求操作时，可以选择一个已经完成并保留在历史列表中的真实 Run，现场切换 Agent、程序和回执；如果时间允许，再启动新的快速任务展示实时流动。不要为了追求“现场现跑”让答辩停在模型等待页面。

## 会场前准备

后端默认使用 `127.0.0.1:8765`。若 `studio-ui/dist` 已构建，FastAPI 会直接提供前端；开发模式的 Vite 地址为 `127.0.0.1:5173`。

```bash
cd /home/qcrs/statebus/project
bash scripts/run_statebus_studio.sh
```

启动脚本在容器内会加载 `docker/activate_statebus_container.sh`，宿主机则使用项目自己的 `$HOME/statebus/conda-envs/statebus_host`，不会安装或修改系统/base Python。脚本把 Embedding 固定到物理 GPU 2、进程内 `cuda:0`，只健康检查并复用现有 vLLM，不负责重启服务。

答辩前至少完成以下检查：

- 顶部 `vLLM` 显示“服务正常”。
- `Embedding` 显示“GPU 就绪”。
- `任务队列` 显示“单 Worker”。
- “运营指标 IQR 异常分析”配方可见，任务 ID 为 `formal-anomaly-001`。
- 至少保留一个成功的快速任务 Run，能够打开四 Agent、程序、回执、产物和质量记录。
- 左侧栏可以收起，浏览器缩放与投影比例下没有遮挡。
- “新建运行”能够清空当前工作台，但历史 Run 仍保留。
- 90 秒真实 Run 录屏在本地可离线播放，不依赖网络。

## 90 秒主讲脚本

### 0—10 秒：健康状态与受控入口

**操作：** 打开“任务演示”页，指向顶部三个健康项和快速任务卡片。

**讲解：**

> 这是 StateBus Studio 的受控运行页。顶部显示现有 vLLM、Embedding 和单 Worker 队列状态。浏览器只能选择后端白名单中的 recipe，不能提交 Shell、路径或任意 Python 参数。这里选择的是正式运营数据中的 IQR 异常检测任务。

### 10—25 秒：Planner 与任务合同

**操作：** 开始播放 Run，Planner 节点高亮；打开或指向当前 Agent 输入/输出区。

**讲解：**

> Planner 接收到的不是一段模糊问题，而是预编译的 CanonicalTaskSpec，其中已经固定任务族、异常检测 intent、目标列、IQR 方法、必需输出、允许工具和质量检查。模型只提出 PlanProposal，Runtime 通过 PlanPolicy 后才形成 ApprovedPlan。

### 25—42 秒：Retriever 与非文本状态

**操作：** 流程进入 Retriever，指向 EvidencePack、StateRef 或状态事件。

**讲解：**

> Retriever 在获准数据范围内形成 EvidencePack，并把 query 和候选保持为 float32 语义状态。控制面只传 SemanticStateRef；不同 PID 的 Selector 读取同一数值对象、执行 top-k，再返回 selected IDs、分数和消费回执。LLM 只看到选择后的局部原始证据。

### 42—65 秒：Executor、代码与验证

**操作：** 流程进入 Executor；切换到“程序”或当前 Agent 代码面板，显示 Python/DSL、Policy、sandbox 和 Artifact 状态。

**讲解：**

> Executor 获得的是 CapabilityGrant 和验证输入。当前 adaptive 配方会生成受限 Python；源码先经过 AST 与路径 Policy，再在非 root bubblewrap 中执行。即使进程退出为零，文件也只是 candidate；schema、IQR 业务事实和 provenance 全部通过后，Runtime 才发布 verified ExecutionArtifactRef。

### 65—80 秒：Summarizer 与最终结论

**操作：** Summarizer 变为完成态，指向最终结论与质量状态。

**讲解：**

> Summarizer 不能读取失败产物，只消费完整 EvidencePack 和 verified Artifact，形成带引用的 ClaimSet。这里最终结论、产物 hash 和质量报告能够互相对应，说明答案来自真实执行链，而不是界面拼出来的一段文本。

### 80—90 秒：事实来源与收束

**操作：** 快速打开“完整记录”中的回执/质量页，或指向已完成的四节点和结果区。

**讲解：**

> 页面中的节点状态和连线来自真实 SSE 事件与 Run 目录重建，不展示模型内部思维链。一次任务从计划、状态、程序到结论，都可以回到具体 Ref、回执和 Validator。

## 现场交互版操作顺序

如果评委要求现场点击，按以下顺序执行：

1. 收起左侧栏，让四 Agent 流程和下方详情尽量在一屏内完整显示。
2. 确认三个健康项为绿色；任何关键项异常时不创建新 Run。
3. 选择“运营指标 IQR 异常分析”，点击“开始运行”。
4. 保持自动跟随开启，让 Agent inspector 随 Planner、Retriever、Executor、Summarizer 切换。
5. 到 Executor 后点击固定该 Agent，展示生成程序、Policy、sandbox 与产物验证；随后重新开启自动跟随。
6. 完成后展示最终结论与质量门，再打开完整记录中的“回执”和“质量”。
7. 点击“新建运行”说明它只复位当前工作台，不删除历史 Run；不要在答辩最后再启动第二个长任务。

## 扩展到 2—3 分钟时可以增加什么

若演示时间充足，可以先用 20 秒打开“实验与证据”页，指出固定证据快照与临时 Run 分离，四个主指标与 PPT 一致；随后进入 Live Studio 完成上述 90 秒任务流；最后打开任务与数据抽屉，展示数据集字段、checksum、任务合同和 Validator，但不要在运行前展示 golden answer。

也可以选择已经完成的“跨期收入三步任务链”，回看 R1、R2、R3 的依赖和记忆使用。该配方适合解释 MemoryRef，但运行约 3—8 分钟，不适合作为现场首次启动任务。

## 故障预案

### 健康检查显示异常

不要反复点击“开始运行”，也不要在会场重启 vLLM。立即切换到预录视频或成功的历史 Run，并说明 Studio 会在关键依赖未就绪时阻止创建必然失败的作业，这是 fail-closed 的产品行为。

### 新 Run 长时间停留在 Planner 或排队

保留页面作为真实状态证据，切换到已完成 Run 继续讲解。不要打开原始 console 占满投影，也不要并发创建多个任务；单 Worker 是为了保护 GPU 资源和正式运行口径。

### 某个 Agent 失败

界面会冻结在失败节点并显示中文阶段与原因。若时间允许，可用十秒说明失败不会被伪装成成功，随后切换到成功 Run；若时间紧，直接播放备用视频。不要现场修改参数、绕过 Validator 或改用未批准 fallback。

### 页面状态残留或第二次显示为空

先点击“新建运行”复位工作台，再选择历史 Run 或配方。该按钮只清空前端 selected Run、flow、task、artifact、role 和 drawer 状态，磁盘 Run 不会删除。

### 前端无法加载

优先播放本地视频。若只需验证后端，可访问 `http://127.0.0.1:8765/api/v1/system/health`，但不要把 API JSON 当成主要作品演示。

## 演示中不要做的事

- 不在网页中输入或展示任意 Shell 命令。
- 不为了“看起来智能”展示或虚构模型思维链。
- 不把历史 Run 自动当成最新正式实验结果。
- 不在会场启动完整效率矩阵、双任务族十轮或 25 任务能力覆盖。
- 不把 quick task 的一次时延当成正式性能证据。
- 不把界面上的流程动画当成机制证明；机制证明来自 Ref、PID、hash、Validator 和持久化 Run。
