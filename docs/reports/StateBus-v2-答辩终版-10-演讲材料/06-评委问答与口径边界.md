# 评委问答与口径边界

下面的“短答”适合先在 15—25 秒内回应；评委继续追问时，再使用“展开”。不要一开始就把所有实现字段全部倒给评委。

## 项目定位

### StateBus 和普通多 Agent 工作流框架有什么区别？

**短答：** 普通框架主要解决节点如何编排，StateBus 重点解决节点之间交接的对象怎样被授权、消费、验证和回收。四个 Agent 仍负责语义任务，Runtime 管理的是 TaskSpec、Grant、StateRef、ArtifactRef、MemoryRef 和回执。

**展开：** LangGraph 一类框架可以表达图和共享 state，但把什么写入 state、谁能看、对象何时可信，通常仍由应用自己约定。StateBus 把这些约定变成 typed Protobuf 控制面、CapabilityGrant、Ref Registry、Validator、Compatibility Gate、Telemetry 和 GC。Studio 可以使用图形界面呈现任务流，但核心能力并不依赖 UI 动画。

### 项目的创新是不是把几种已有技术拼在一起？

**短答：** 单独使用 Protobuf、shared memory、向量检索或沙箱都不是我们的创新点。创新在于用统一身份链和状态提升规则把它们接成一个 Runtime：模型输出都是候选，只有经过授权、消费回执和质量门，才能成为下游可见对象。

**展开：** 控制合同限制状态与产物的可见范围；SemanticStateRef 的消费结果改变 EvidencePack；MemoryRef 必须兼容并真实进入 RoleView；CodeAct 只发布 verified Artifact。实验也不是分别跑四个孤立 Demo，而是完整链、机制真实性、连续任务和能力覆盖四层证据。

### 为什么是四个 Agent？赛题不是只要求三类吗？

Planner、Retriever、Executor、Summarizer 分别覆盖计划、检索、执行和总结。四角色让“提出计划”“取得证据”“产生可验证产物”“组织带引用结论”保持职责分离，同时超过赛题不少于三类 Agent 的要求。25/25 能力任务均观测到四角色进入主链。

## 结构化通信与授权

### 结构化通信不就是 JSON 换成 Protobuf 吗？

不是。Protobuf 只解决稳定编码和解析，StateBus 的关键是字段进入 Runtime 语义：task/step/attempt 绑定身份，target role 和 capability 绑定权限，Ref 绑定输入对象，ACK/heartbeat/terminal result 绑定生命周期，output contract 和 Validator 决定结果能否被消费。P22 的专项还保持 50 条逻辑消息不变，说明节省不是删掉协作，而是控制载荷本身变小。

### Planner 已经生成计划，为什么还需要 PlanPolicy？

Planner 的输出是 `PlanProposal`，它可能在 schema、角色、依赖、能力、预算或输出合同上不合法。PlanPolicy 将模型建议与任务注册表、能力目录和质量要求交叉检查，产生 `ApprovedPlan`。模型提议和系统批准分离，避免 Planner 通过一句自然语言给自己扩大权限。

### CapabilityGrant 和普通权限检查有什么不同？

Grant 不是一个布尔值。它绑定当前 task、session、step、attempt、capability ID/version、批准计划 hash、输入 Ref、输出合同、workspace、超时和到期时间。即便计划曾经合法，Dispatcher 在发送前仍会检查当前 Ref 是否仍 verified、hash 和 manifest 是否变化、lease 是否有效。

### 为什么还要 ACK、RunStart、Heartbeat？

它们区分“消息被完整接收”“前置校验后开始运行”和“当前 attempt 仍存活”。没有这组状态，ACK 超时、Worker 运行中失联和业务执行失败会被混成同一种异常，也无法阻止旧 attempt 的晚到结果污染新 attempt。

## 非文本状态

### LLM 会直接读取 embedding 或共享内存矩阵吗？

不会。Retriever 发布 query/candidate `float32` 矩阵，独立 PID 的数值 Selector 解析 `SemanticStateRef` 并执行 top-k。Selector 返回 selected IDs、行号、分数和 PIDs，Runtime 再依据 HydrateManifest 局部加载对应的原始证据，LLM 读取的是这部分文本或结构化证据。

### 只传 shared memory 名称不是更简单吗？

名称只能定位一块内存，不能证明类型、来源、shape、dtype、encoder、内容 hash、owner、lease 和对象状态。`SemanticStateRef` 还要和 sidecar、Registry、CapabilityGrant 交叉验证，消费后留下 producer/consumer 回执并完成释放。

### 如何证明不是“发布了状态但实际没用”？

正式主张同时检查四件事：发布了多少物理对象；consumer PID 是否与 producer PID 不同；selected IDs 是否改变了下游 decision surface；最后是否释放。P23 的结果是 9/9 跨 PID 消费、9/9 改变选择、27 次选中证据，并且 294,912 B 全部释放。

### 这是 hidden state 或 KV cache 传递吗？

不是。PPT 主机制传递的是 embedding 和 query/candidate 稠密矩阵。完整词表 logits、hidden state 和 KV cache 跨引擎传递不属于正式基线；只能作为 Engine-Local Prefix Reuse 的后续方向。PPT 文件中的早期 Latent KV 备注已经过时，不应作为当前实现说明。

### 新增 Logit Retry Gate 与 SemanticStateRef 有什么区别？

`SemanticStateRef` 服务于检索证据选择，载荷是 query/candidate embedding 矩阵；`LogitStateRef` 服务于 Executor 闭集候选的执行前授权，载荷是 candidate probabilities 加 `other_mass`。Logit Gate 由独立 PID 判断 top-1 与 margin，决定 accept、最多重查一次或 fail closed。

该机制是 7 月 27 日的独立受控补充：12 个 case 的 Validator 从 Gate off 的 8/12 提升到 retry-once 的 12/12，19/19 数值状态跨 PID 消费并释放。它不属于 PPT 的 95/95 固定基线，也不用于声称 Token 或时延收益。

## 共享记忆

### 为什么有候选的查询是 18/20，实际使用却只有 7/20？

18/20 只说明检索阶段找到了语义或关键词相似的历史。候选还要经过任务意图、schema、manifest、lineage、Runtime、Validator 和目标角色可见性检查。真正进入 RoleView 并留下 consumption record 的只有 7 次，所以 actual-use 是 7/20。

### 81.25% 的候选都被拒绝，是不是说明记忆系统不好？

不是。48 个候选是宽召回结果，39 个被兼容门拒绝说明系统没有把相似历史无条件注入当前任务。拒绝不是任务失败，Runtime 会记录原因并用当前输入重算。记忆系统同时需要“能发现可复用机会”和“能阻止不安全复用”。

### actual-use 是否一定代表节省了 LLM 调用？

不一定。actual-use 表示记忆真实进入角色输入并被消费；behavioral effect 进一步表示它改变了选择、减少工作或跳过步骤。当前 7 次 actual-use 都有行为效果，2 次跳过执行步骤，但不能据此宣称跳过了 7 次 LLM call。消费、效果、跳步和跳过调用是不同指标。

### 为什么使用 RRF？

关键词、标签和向量检索的分数尺度不同，直接相加会引入不可比性。RRF 使用各来源中的名次融合候选，降低分数尺度影响，并以稳定 memory ID 处理同分。但 RRF 只排序，不能绕过 Compatibility Gate。

## CodeAct、DSL 与产物

### 25 个能力任务中的 18 和 7 是什么意思？

18 个任务使用受限 Python CodeAct 表示，7 个使用 Transform DSL，合计 25 个，并全部通过统一 Validator。它们是执行表示的任务分布，不是 Python 与 DSL 的优劣对照。

### 18 个 Python 任务都是 LLM 临场生成代码吗？

不能这样表述。正式 benchmark 为稳定测量 Runtime，可以使用注册的 `deterministic_codeact` recipe；adaptive CodeAct 路径才由 LLM 在约束下生成 Python。两者都会经过 workspace 和 Validator，但只有 adaptive 路径能声称“LLM 临场生成受限 Python”。P25 的 18/18 证明受限 Python 执行路径覆盖，不等于 18 次自由生成。

### 模型代码怎么保证安全？

三层边界分别处理不同风险。AST/Policy 拒绝危险导入、动态执行和越权路径；非 root bubblewrap 关闭网络、只读输入、限制写目录和资源；业务 Validator 检查 schema、数值事实、独立重算和来源链。任何一层失败都不能回退到宿主机任意执行。

### 程序退出码是 0，为什么还不能直接用？

退出码只说明进程没有以错误状态退出，不说明季度、指标、公式、字段或来源正确。文件先登记为 candidate，只有 schema、业务事实、provenance 和 Commit Gate 通过，才变成 verified `ExecutionArtifactRef`，Summarizer 才能读取。

### fallback 为 0 是什么意义？

25 个能力任务都通过批准的 Python 或 DSL 主路径完成，没有依赖预置兜底答案掩盖失败。它不表示系统没有失败处理，而是这批正式任务没有触发执行 fallback。

## 实验与数字

### 95/95 是 95 个不同任务吗？

不是。95 是正式执行记录数：40 次同任务四配置、20 次连续任务、10 次机制真实性和 25 次能力覆盖。任务能力族和运行次数是不同分母，P20 已明确分开。工程回归测试也不计入 95。

### 为什么完整链质量没有下降？

对照保持同任务、同输入、同模型、同角色链和同一 Validator。StateBus 减少的是重复文本、控制载荷和不必要的证据暴露，不删除必要角色和质量检查。所有产物仍要通过统一输出和业务质量门。

### Token 和 wire bytes 有什么区别？

Token 是模型调用的 prompt 加 completion 数量，反映模型可见上下文和生成负担；wire bytes 是 UDS 线路上传输的序列化消息字节，反映控制面和引用交接负担。一个结构化对象可以减少线路字节，但若仍被渲染进 Prompt，Token 不一定同比下降，因此两者需要分别统计。

### 时延降低 6.32% 能否推广到所有任务？

不能做无条件推广。该数字来自固定基线下 10 个匹配任务的串行总 `task_ms`，315.678 秒降至 295.728 秒，是这组任务和环境的描述性结果。它说明在长证据、Token 压缩明显的任务上，减少模型时间可以覆盖 Runtime 固定成本；不同负载仍可能有不同拐点。答辩主结论应是固定范围内质量保持、综合通信负担下降，而不是宣称所有任务必然加速。

### P22 为什么同时出现 L0/L3 和 L0/L1？

它们回答不同问题。L0/L3 是纯文本对完整 StateBus 的完整链比较；L0/L1 是纯文本对结构化协议的控制面专项。编号只是配置标签，不应包装成严格的相邻层级消融或把两个结果混成一个因果分解。

### 558 passed 和 582 passed 哪个是当前数字？

PPT 与项目说明书的固定证据快照是 558 passed，对应 `bda1774` 和正式 95/95 基线。加入 Logit Retry Gate 后，当前代码全量 `tests/v2` 为 582 passed。主讲 PPT 时按页面说 558；如果问当前仓库，再说明 582，并强调新增测试没有重写正式业务实验。

### 数据来源在哪里？

P20—P25 的主数字来自 [StateBus-v2-最终实验结果与PPT绘图数据-20260726.md](../StateBus-v2-最终实验结果与PPT绘图数据-20260726.md)，正式代码/实验基线为 `bda1774`。原始 Run 没有上传到 Git，但本地证据目录、汇总报告和来源路径保留。Logit Gate 使用独立的 2026-07-27 报告和 Run，不合并分母。

## 交付与演示

### openEuler 是真实验证还是目标描述？

P25 对应 openEuler 24.03 LTS-SP3 单容器验证。准确表述是项目的容器交付形态在该环境完成验证，不扩展为所有 openEuler 版本、所有硬件或宿主环境都已验证。

### Studio 页面展示的是真实任务吗？

是。前端通过白名单 recipe 创建后端 Run，JobManager 启动现有 Runner，SSE 和 task-flow adapter 从真实 JSONL、summary、Artifact 和 Validator 记录重建流程。React Flow 动画对应 step/event 状态，不展示或伪造模型内部思维链。

### 为什么浏览器不能直接输入 Shell 或任意路径？

Studio 是受控运行产品，不是远程终端。浏览器只能提交 catalog 中的 recipe ID；后端构造固定 argv，校验项目路径和数据范围，并使用单 Worker 队列。这样演示接口不会成为任意命令执行、模型服务重启或越权文件读取入口。
