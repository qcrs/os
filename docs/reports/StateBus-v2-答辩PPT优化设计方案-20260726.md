## 3. 难点章定位(v4)

**难点的本质：三个机制的系统性边界——不是实现时踩的坑，而是该领域本身的根本难题，以及系统如何划定边界来应对。**

评委看完亮点章后会隐性追问："这些机制在什么条件下会失效？你怎么保证它是可信的？"难点章就是在回答这个问题。讲法不是"我们遇到了 XX 问题后来用 YY 方法解决了"，而是"这个机制本身存在一条边界，越过它就会失效，系统用这个策略来守住这条边界"。评委获得的是**可信感**，而不是踩坑分享。

三个难点的重新表述：

| 支柱 | 难点标题 | 边界在哪里 | 守边界的策略 |
|---|---|---|---|
| 通信 | 协议格式合法 ≠ 执行语义合法 | 格式验证与语义授权是两个独立的层 | Policy 层：能力 / 依赖 / 合同 / 风险四项前置检查 |
| 状态 | 对象物理可读 ≠ 语义可信 | 共享内存可被任何进程打开，身份与完整性需独立校验 | StateRef provenance 链：六项打开前校验 |
| 记忆 | 语义相似 ≠ 跨任务兼容 | 相似度衡量文本距离，不衡量期间/口径/血缘兼容性 | CompatibilityGate：三项独立兼容判断 |

**每页结构：边界 40% + 系统策略 60%**
- 上区 40%：边界是什么——一句话核心矛盾 + 最典型的失效场景（一行具体例子）
- 下区 60%：系统怎么守这条边界——判断条件+处置结果的表 + 一个辅助小图示

**图形选择**：每页表格 + 小图示组合，不全用表格：
- P14(通信)：四项检查宫格 + 右侧韦恩图（"格式合法" ⊃ "可执行"，Policy 层是中间圈）
- P15(状态)：六项校验宫格 + 右侧状态路径图（"打开"和"正确"两个节点，中间是校验关卡）
- P16(记忆)：四情形判定表 + 右侧漏斗局部放大（兼容层高亮，候选在此被筛选）

**P14 转场页已取消**，三个难点页编号 03·01 / 03·02 / 03·03，正文合计 25 页。
