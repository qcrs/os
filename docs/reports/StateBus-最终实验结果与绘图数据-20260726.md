# StateBus 最终实验结果与绘图数据

更新日期：2026-07-29

用途：作为技术文档中的实验章节，集中给出任务定义、数据集、对照关系、图表数字和结论边界。本文只记录已经存在的本地实验，不把不同 run、不同任务数或不同统计分母拼成一个结论。

## 1. 先读：实验地图与统计口径

### 1.1 最容易混淆的两个数字

**“两组各 10 轮”不是 20 组任务。** 它表示 Operating 连续链 10 轮，加上 Financial 连续链 10 轮，共 20 个按顺序运行的任务。后续轮次会依赖前序任务产生的 schema、统计结果、证据定位、策略或 lineage，用于观察共享记忆是否在自然连续任务中被查询、通过兼容门并实际消费。

**“五类 25 个任务”不是五组各 25 个任务。** 它表示五个任务族合计 25 个固定任务：财报指标抽取 8 个、多期趋势 5 个、跨表关联 5 个、条件聚合 4 个、异常检测与清洗 3 个，即 `8 + 5 + 5 + 4 + 3 = 25`。

另外还有三组较小但用途不同的证据：

- 10 个匹配消融任务：Operating 5 个 + Financial 5 个，在 L0/L1/L2/L3 四条 lane 中各运行一次。
- 4 个非文本状态 holdout：验证状态是否跨进程消费、改变选择并完成释放。
- 6 个记忆机制 case：5 个顺序兼容复用 case + 1 个不兼容记忆负例。

### 1.3 统计单位必须分开

| 单位 | 含义 | 本文示例 |
| --- | --- | --- |
| 唯一任务 / canonical task | 一个固定输入和目标定义 | E1 为 10 个，E5 为 25 个 |
| 执行 / run case | 某个任务在某条 lane 上运行一次 | E1 为 40 次执行 |
| 查询级 | 一个任务是否发起记忆查询、获得候选或 actual-use | E2 actual-use 为 `7/20` |
| 候选级 | 检索返回的每条候选是否兼容 | E2 为 9/48 兼容、39/48 拒绝 |
| consumption/effect receipt | 某个角色消费记忆后产生行为效果的记录 | E2 为 9/9，E3 为 23/23 |
| pair | 同一任务的 no-memory 与 memory 两次执行 | development paired 为 6 对，4 对 digest 有效 |

“有候选”不能写成“命中”，“兼容候选”不能直接写成“实际复用”，角色 receipt 数也不能写成任务数。

### 2.4 第 22 页：L0 纯文本 vs L1 结构化控制

这页仍然使用 E1 的同一批 10 个任务，只切换控制面载体；semantic state 和 memory/replay 均保持 OFF。

v14 的横向堆叠条把线路字节拆成 `control bytes + 其他 wire bytes`：

| 分组 | lane | 逻辑消息 | control bytes | 其他 wire bytes | total wire bytes | 质量 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |

结构化载荷至少覆盖 Action Type、Parameters、Result、Capability，并支持 Handshake/Mapping。这里的因果变量是控制面编码方式，不是减少协作轮次，也不是提前打开 semantic state 或 memory。

> 相同 50 条逻辑消息、相同 10/10 质量下，仅打开 typed Protobuf 控制面，control bytes 降低 83.05%，wire bytes 降低 68.95%。

## 3. PPT 第 23 页：非文本状态的效果与机制闭环

### 3.1 为什么需要两层证据

第 23 页左、右两部分来自不同实验，回答的问题也不同：

- 左侧使用 E1 的 L1 vs L2。L1 已经采用 typed Protobuf，但没有 semantic state；L2 只增加 semantic pruning/state，用于观察原始证据暴露和 Token 的变化。
- 右侧使用 E4 的 4 个独立 holdout，用于证明数值状态确实由另一 PID 消费、改变 evidence selection，并在任务结束后释放。

因此，左侧是效果对照，右侧是机制真实性。不能把 E4 的 `294,912 B` 当作 E1 L1/L2 柱状图的字节分母。

### 3.2 左侧：E1 的 L1 vs L2 效果对照

按任务组的主图数据：

| 分组 | raw evidence bytes L1 -> L2 | 变化 | Total Token L1 -> L2 | 变化 |
| --- | ---: | ---: | ---: | ---: |
| Operating | 48,336 -> 5,493 | `-88.64%` | 20,425 -> 8,477 | `-58.50%` |
| Financial | 24,930 -> 6,200 | `-75.13%` | 14,466 -> 9,262 | `-35.97%` |
| Overall | 73,266 -> 11,693 | `-84.04%` | 34,891 -> 17,739 | `-49.16%` |

完整的总体指标：

| 指标 | L1 结构化控制 | L2 + semantic state | 变化 |
| --- | ---: | ---: | ---: |
| raw evidence bytes exposed to LLM | 73,266 | 11,693 | `-84.04%` |
| Prompt Token | 30,737 | 13,599 | `-55.76%` |
| Completion Token | 4,154 | 4,140 | `-0.34%` |

## 4. PPT 第 24 页：共享记忆的实际使用、安全性与节省潜力
