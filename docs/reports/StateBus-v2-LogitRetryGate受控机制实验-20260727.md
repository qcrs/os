# StateBus v2 Logit Retry Gate 受控机制实验

> 实验性质：独立受控诊断，不更新现有 `95/95` 正式实验基线。
>
> 有效运行目录：`/home/qcrs/statebus/runs/logit_retry_challenge_20260727_222823`
>
> 运行环境：`statebus-dev-qcrs` 容器、现有 `qwen3-32b` vLLM 服务；本地模型设备按物理 GPU 2 / 容器内 `cuda:0` 配置。

## 1. 要验证的问题

普通任务通常会让模型直接给出高置信选择，无法证明 Logit 状态真的改变了 Runtime 的执行行为。因此本实验不统计“自然任务重试率”，而是构造三类有明确作用的受控任务：

1. **简单对照**：合同从一开始就足够清楚，用于验证 Gate 不会无故触发重试。
2. **受控歧义**：首次只提供最小 RoleView，使两个候选在可见信息下等价；Gate 检测到低 margin 后，Runtime 才展开完整合同并重选。
3. **不可判定负例**：即使展开合同仍没有合法选择，用于验证第二次低置信时能否阻止 Worker dispatch。

核心问题不是“模型能否再次回答”，而是：

> 模型产生的数值概率能否作为非文本状态被独立进程消费，并真实决定继续执行、重试或关闭执行。

## 2. 机制与判定规则

```text
最小 RoleView
      |
      v
模型选择候选 + 真实候选概率
      |
      v
AB/BA 反事实校准
      |
      v
float32 LogitState --shared_memory--> 独立 PID Gate
      |
      +-- selected 为 top-1 且 margin >= 0.10 --> 授权进入 Worker dispatch 边界
      |
      +-- margin < 0.10 --> 展开完整合同，仅重试一次
                                  |
                                  +-- 通过 --> 执行
                                  +-- 仍不通过 --> fail closed
```

### 为什么使用 AB/BA 校准

真实 vLLM 预实验发现，受约束 JSON 选择对第一个别名 `A` 有很强的位置偏差。直接采用单次 `A/B` 概率，会把格式偏好误当成任务置信度。

正式诊断对同一 RoleView 做两次真实请求，交换候选与 `A/B` 的绑定，再按候选 ID 对齐概率并取均值。这样能抵消首项偏差。`AB/BA` 只存在于审计数据中，不作为提示信息暴露给模型。

### 公平性约束

- `off` 与 `retry_once` 使用同一任务、同一模型、同一候选和相同首次 RoleView。
- 两种模式的首次选择均使用相同的 AB/BA 校准，且 12/12 配对任务的首次选择一致。
- Gold 与模型可见 manifest 分离，预期答案不进入提示词。
- 24 次运行串行执行；任务顺序采用交替的 `off/retry_once` 与 `retry_once/off`。
- `off` 不发布 LogitState、不调用 Gate、不重试；`retry_once` 最多只重试一次。

## 3. 任务设计

| 分组 | 数量 | 代表任务 | 预期作用 |
|---|---:|---|---|
| 简单对照 | 5 | 异常检测、相关性、跨期趋势、聚合极值、DSL 路由 | 首次直接通过，验证无误触发 |
| 受控歧义 | 5 | 异常检测、跨表连接、跨期趋势、聚合极值、Python/DSL 选择 | 首次低 margin，展开合同后完成正确路由 |
| 不可判定负例 | 2 | 完全等价副本、均缺少授权的计划 | 第二次仍低 margin，禁止产生 Worker 放行判定 |

五个受控歧义任务是本实验的主展示组。首次提示只说明“读取已验证输入并产生结构化结果”；重试时才分别展开 IQR 输出、连接键、多期序列、极值输出或 Python/DSL 能力边界。

## 4. 最终结果

### 4.1 分组结果

| 分组 | Gate off | Retry once | 重试触发 | 结果变化 |
|---|---:|---:|---:|---|
| 简单对照 | 5/5 | 5/5 | 0/5 | 没有误触发 |
| 受控歧义 | 3/5 | 5/5 | 5/5 | 2 个错误路由被纠正 |
| 不可判定负例 | 0/2 | 2/2 | 2/2 | 错误放行判定从 2 降为 0 |
| **全部 Validator** | **8/12** | **12/12** | **7/12** | **机制效果门 PASS** |

受控歧义组中，5 个任务均在低 margin 后展开合同并在第二次被 Gate 接受。其中 2 个任务改变了候选选择；其余 3 个任务首次碰巧选对，但仍需展开合同才能获得足够的数值授权依据。

### 4.2 非文本状态与跨进程闭环

| 指标 | 结果 |
|---|---:|
| Gate 数值状态尝试 | 19 |
| 跨 PID 真实消费 | 19/19 |
| 生命周期正确释放 | 19/19 |
| 单次状态大小 | 12 B |
| 发布并释放的状态总量 | 228 B |

每次状态由两个候选概率和一个 `other_mass` 组成，即 3 个 little-endian `float32`。控制面只传 `LogitStateRef`；独立 Gate 进程读取 shared memory、校验哈希与租约、计算 margin 并返回结构化回执，随后 Runtime 释放状态并留下 tombstone。

### 4.3 机制成本

| 模式 | vLLM 调用 | 总 Token |
|---|---:|---:|
| Gate off | 24 | 6,110 |
| Retry once | 38 | 9,952 |

这组实验的目标是验证控制机制，不是证明性能收益。AB/BA 校准使每个选择阶段需要两次模型请求，7 个低 margin 任务又增加了二次选择，因此调用和 Token 均会上升。该开销必须与机制结果一并披露。

## 5. PPT 建议表达

主图只展示一条因果链：

```text
最小合同下低 margin
        -> Runtime 展开完整合同
        -> 5/5 歧义任务二次通过
        -> 2 个错误路由被纠正

第二次仍低 margin
        -> fail closed
        -> 不可判定任务 Worker 放行判定：2 -> 0
```

右侧放机制真实性锚点：

```text
19/19 跨 PID 消费
19/19 正确释放
float32 / shared_memory / GateReceipt
```

建议标题：

> **Logit Retry Gate｜让模型数值状态真正决定“执行、重试或拒绝”**

建议结论：

> 在 5 个受控歧义任务中，Gate 触发 5/5 上下文升级并使路由结果达到 5/5；在 2 个不可判定负例中，系统将错误放行判定从 2 次降为 0 次。19 次数值状态均由独立 PID 消费并完成释放。

## 6. 结论边界

- 这是特意构造的机制挑战，不代表线上或自然任务中的重试发生率。
- `12/12` 是本诊断套件的 Validator 结果，不能与正式基线的 `95/95` 合并。
- 结果证明的是“Logit 状态能够改变控制流”，不是 Logit Gate 带来 Token 或时延收益。
- 挑战套件在 Worker dispatch 边界结束，验证的是路由与授权决策，不包含下游业务计算；Runtime 的端到端接入由回归测试覆盖。
- 当前状态是候选级概率向量，不是完整词表 logits、hidden state 或 KV cache。
- 最终展示应同时保留简单对照、歧义挑战和不可判定负例，避免只展示成功重试而遗漏误触发与 fail-closed 检查。
