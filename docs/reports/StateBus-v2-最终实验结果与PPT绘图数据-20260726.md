### 1.2 一句话总结

> 在同任务、同模型、同角色链和同质量门的对照中，StateBus 将总 Token 降低 47.40%、wire bytes 降低 64.85%、总耗时降低 6.32%，并在后续专项任务中验证了非文本状态的跨进程真实消费和共享记忆的跨任务实际使用。

## 2. 到底测了哪些任务

整套实验不是将一批无关任务堆在一起，而是按“性能对照 -> 连续复用 -> 机制真实性 -> 能力覆盖”逐层扩展。

### 2.1 任务分层全景

| 任务层 | 规模 | 任务内容 | 主要回答的问题 |
| --- | ---: | --- | --- |
| 同任务效率对照 | 2 类 x 5 轮 x 4 配置 = 40 次执行 | Operating 5 件 + Financial 5 件 | 纯文本与 StateBus 在 Token、通信、耗时和质量上的差异 |
| 连续任务 | 2 类 x 10 轮 = 20 次执行 | 前 5 轮基础任务 + 后 5 轮长链扩展 | 系统能否连续运行，历史记忆是否进入后续任务 |
| 记忆真实性 | 6 次执行 | 连续财务任务 + 1 个不兼容记忆用例 | 候选、兼容、消费、行为效果和拒绝重算是否可追踪 |
| 非文本状态 | 4 次 holdout | 2 个长文本、1 个表格对照、1 个文本+表格 | 数值状态是否被另一进程消费并改变选择 |
| 能力覆盖 | 5 类 x 25 次执行 | 抽取、趋势、跨表、条件聚合、异常检测 | 四角色链、CodeAct/DSL 和质量门能否在多类任务上闭环 |

| 展示名称 | 实验含义 | 用于回答 |

| 完整 StateBus | 结构化控制、语义选择/状态传递和兼容门记忆全部打开 | 整套系统相对纯文本的端到端结果 |

## 4. 完整链效率结果

### 4.1 十个同任务的整体对比

| 指标 | 纯文本协作 | 完整 StateBus | 变化 |
| --- | ---: | ---: | ---: |
| 任务数 / 质量通过 | 10 / 10 | 10 / 10 | 质量保持 |
| Agent 消息数 | 50 | 50 | 0 |
| control bytes | 25,196 | 5,357 | `-78.74%` |
| wire bytes | 36,069 | 12,677 | `-64.85%` |
| LLM 可见原始证据字节 | 73,266 | 11,687 | `-84.05%` |
| Prompt 可见字节 | 75,926 | 15,847 | `-79.13%` |
| Prompt Token | 29,876 | 13,885 | `-53.52%` |
| 总 Token | 33,974 | 17,870 | `-47.40%` |
| 10 任务总耗时 | 315.678 s | 295.728 s | `-6.32%` |

适合 PPT 的结论：

> 在 10 个同任务、同质量的串行对照中，StateBus 同时实现总 Token 下降 47.40%、wire bytes 下降 64.85% 和任务总耗时下降 6.32%。

### 4.2 时延数字如何权衡

时延主页必须使用全部 10 个匹配任务的总结果；Operating 只作为任务族的增强信息，不替代整体结果。

| 展示层级 | 数据 | 视觉权重 | 建议标题 |
| --- | --- | --- | --- |
| 主结果 | `315.678 s -> 295.728 s`，`-6.32%` | 约 70% | `10 任务总耗时下降 6.32%` |
| 任务族亮点 | `159.896 s -> 131.551 s`，`-17.73%`，5/5 更快 | 约 30% | `Operating 任务中降低 17.73%` |

推荐布局：左侧放整体耗时双柱图和 `-6.32%` 大数字；右下角放一张较小的 Operating 任务卡，明确标注“5 个子集任务”和“5/5 更快”。两个百分比不做并列系统总指标。

## 5. 按赛题重点展开结果

### 5.1 低开销结构化通信

这一页只回答“相同消息数下，线路载荷是否减少”。

| 指标 | 纯文本 | 结构化协议 | 变化 |
| --- | ---: | ---: | ---: |
| 任务质量 | 10/10 | 10/10 | 保持 |
| Agent 逻辑消息 | 50 | 50 | 0 |
| control bytes | 25,196 | 4,270 | `-83.05%` |
| wire bytes | 36,069 | 11,200 | `-68.95%` |

页面主句：

> 不减少协作轮次：在相同 50 条 Agent 消息下，结构化协议将控制面字节降低 83.05%、总线路字节降低 68.95%，质量保持 10/10。

### 5.2 非文本中间状态传递

这一页不讲类定义，只展示状态生命周期上的四个实测检查点。

| 检查点 | 实测结果 | 说明 |
| --- | ---: | --- |
| holdout 质量 | 4/4 | 2 个长文本、1 个表格、1 个混合任务全部通过 |
| 使用语义状态的任务 | 3 | 表格任务作为不强制状态的路由对照 |
| 物理数值选择对象 | 9 | 独立的 float32 数值对象 |
| 跨 PID 消费回执 | 9/9 | producer 与 consumer 为不同进程 |
| 改变下游 decision surface | 9/9 | 数值选择确实影响下游证据选择 |
| 被选证据 occurrences | 27 | 不是只 publish 未使用 |
| 发布 / 释放物理字节 | 294,912 / 294,912 B | 发布与释放按字节闭环 |

PPT 图形建议：

```text
3 个语义任务
  -> 9 个数值状态
  -> 9/9 跨进程消费
  -> 9/9 改变下游选择
  -> 294,912 B 全量释放
```

页面主句：

> 非文本状态不只是“发布成功”：9/9 数值状态由另一进程实际消费，9/9 改变下游选择，并完成全量释放。

### 5.3 共享记忆复用

记忆页的主数字是“实际使用率”，不把只检索到候选记忆叫作命中。

#### 自然连续任务漏斗

```text
20 次记忆查询
  -> 18 次找到候选                 90%
  -> 7 次通过兼容门                 35%
  -> 7 次真实消费并产生行为效果   35%
  -> 2 次跳过执行步骤                 10%
```

| 指标 | 数值 | 展示含义 |
| --- | ---: | --- |
| 连续任务质量 | 20/20 | 两组各 10 轮稳定通过 |
| 有候选查询 | 18/20 = 90.00% | 只说明检索到历史 |
| 实际使用查询 | 7/20 = 35.00% | PPT 的记忆主数字 |
| 行为效果查询 | 7/20 = 35.00% | 每次真实使用均有效果记录 |
| 跳过步骤 | 2/20 = 10.00% | 可观察的减少重复工作 |
| 候选记忆 | 48 | 候选级分母 |
| 兼容候选 | 9/48 = 18.75% | 可进入角色输入的候选 |
| 拒绝不兼容候选 | 39/48 = 81.25% | 记忆不被无条件注入 |
| 消费回执 | 9 条，分布于 7 轮 | 一次查询可真实消费多条记忆 |

#### 真实性与安全性补充

| 检查项 | 结果 |
| --- | ---: |
| 任务质量 | 6/6 |
| 记忆 consumption / effect 记录 | 23 / 23 |
| Executor / Summarizer 消费记录 | 8 / 15 |
| 故意不兼容的记忆 | 1 个，被拒绝并对当前任务重算 |
| 严格减少工作 | 跳过 1 个步骤和 1 次 LLM call |

页面主句：

> 在两组 10 轮自然连续任务中，共享记忆实际使用率为 35%，所有实际使用均产生可观察行为效果；同时拒绝 81.25% 的不兼容候选，并在真实性用例中验证了跳过 LLM 调用的实际减少工作。

## 9. 可直接用于实验报告的结果摘要

> 我们围绕赛题的低开销通信、非文本状态传递、共享记忆复用和系统完整性，设计了四层任务集：40 次同任务配置对照、20 轮连续任务、10 个机制真实性用例以及 25 个能力覆盖任务。效率对照固定任务输入、模型、角色链、执行边界、validator 和质量门，只改变协作方式与相应功能开关。

> 在 10 个同任务的纯文本/完整 StateBus 串行对照中，两组质量均为 10/10。StateBus 将 Prompt Token 从 29,876 降至 13,885，降低 53.52%；将总 Token 从 33,974 降至 17,870，降低 47.40%；将 wire bytes 从 36,069 降至 12,677，降低 64.85%；任务总耗时从 315.678 秒降至 295.728 秒，降低 6.32%。在 Operating 子集的 5 个任务中，总耗时从 159.896 秒降至 131.551 秒，降低 17.73%，5/5 任务均更快。

> 结构化通信的单独对照保持 50 条 Agent 逻辑消息不变，control bytes 从 25,196 降至 4,270，降低 83.05%；wire bytes 从 36,069 降至 11,200，降低 68.95%。非文本状态的 4 个 holdout 任务全部通过，3 个语义任务产生 9 个数值状态对象，9/9 由不同 PID 的下游进程消费，9/9 改变下游选择，并完成 294,912 字节的发布/释放闭环。

> 在 Operating 和 Financial 两组各 10 轮的自然连续任务中，20/20 质量通过，共享记忆实际使用率和行为效果率均为 7/20，即 35%，并产生 2 次跳过步骤。候选级共拒绝 39/48 个不兼容记忆，拒绝率为 81.25%。补充真实性用例中，6/6 任务通过，23 条消费记录全部有对应行为效果，故意不兼容的记忆被拒绝并重算，同时观察到 1 次跳过 LLM 调用。

> 在完整的 25 件能力任务中，财报抽取、多期趋势、跨表关联、条件聚合和异常检测五个任务族全部通过，其中 18 件使用受限 Python CodeAct、7 件使用 DSL，无 fallback。工程门进一步完成 135 项聚焦测试和 558 项完整回归测试。
